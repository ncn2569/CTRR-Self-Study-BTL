## Task 1 — Degrees of Separation in a Social Network

### 1.1. Giải thích cách tính h(n)

Trong bài toán mạng xã hội, mỗi đỉnh đại diện cho một người, mỗi cạnh có trọng số 1 đại diện cho một kết nối (friendship). Hàm heuristic h(n) ước lượng **số kết nối tối thiểu** từ node hiện tại đến goal.

**Phương pháp tính h(n): Reverse BFS (BFS ngược) từ goal.**

Thuật toán:

1. Khởi tạo h(i) = +∞ cho tất cả node, đặt h(goal) = 0.
2. Đưa goal vào hàng đợi (queue).
3. Với mỗi node u lấy ra từ queue, duyệt tất cả node i có cạnh i → u (cạnh có hướng chỉ VÀO u).
4. Nếu h(u) + 1 < h(i), cập nhật h(i) = h(u) + 1 và đưa i vào queue.
5. Lặp cho đến khi queue rỗng.

**Tại sao đây là heuristic tốt?**

- BFS ngược tính **chính xác** khoảng cách ngắn nhất từ mỗi node đến goal trên đồ thị có hướng.
- Vì tất cả cạnh có trọng số = 1, BFS cho kết quả tối ưu.
- h(n) luôn ≤ chi phí thực tế → **admissible** → A* đảm bảo tìm đường đi ngắn nhất.

|----------|-----------|----------|---------|
| Init | — | h(4) = 0 | h = [∞, ∞, ∞, ∞, 0] |

## Task 2 — Drone Delivery in 2D Space with Three Heuristics

### 2.1. Ba loại Heuristic

| Mode | Tên | Công thức | Đặc điểm |
|------|-----|-----------|-----------|
| 1 | Manhattan | h = \|x₁ − x₂\| + \|y₁ − y₂\| | Tổng chênh lệch tuyệt đối theo 2 trục. Phù hợp khi di chuyển theo lưới (chỉ ngang/dọc). |
| 2 | Euclidean | h = √((x₁−x₂)² + (y₁−y₂)²) | Khoảng cách đường chim bay. Phù hợp khi có thể di chuyển theo mọi hướng. |
| 3 | Chebyshev | h = max(\|x₁ − x₂\|, \|y₁ − y₂\|) | Khoảng cách lớn nhất theo một trục. Phù hợp khi di chuyển chéo cùng chi phí với thẳng. |

**Quan hệ:** Với mọi cặp điểm, luôn có: **Chebyshev ≤ Euclidean ≤ Manhattan**.

### 2.2. Manual Example Run — So sánh 3 Heuristics

**Đồ thị ví dụ:** 4 node với tọa độ và trọng số cạnh.

```
Nodes:
  A(0) = (0, 0)
  B(1) = (4, 0)
  C(2) = (2, 3)
  D(3) = (4, 3)

Edges (có trọng số):
  A → B: w = 5
  A → C: w = 4
  B → D: w = 2
  C → D: w = 3
  C → B: w = 2
```

```
  A(0,0) ---5--→ B(4,0)
    \               |
     4              2
      ↘             ↓
      C(2,3) --3-→ D(4,3)  [GOAL]
        \--2--→ B
```

**Start = A(0), Goal = D(3).**

Hai đường đi khả thi:

- **Đường 1:** A → B → D, tổng g = 5 + 2 = **7**
- **Đường 2:** A → C → D, tổng g = 4 + 3 = **7**
- **Đường 3:** A → C → B → D, tổng g = 4 + 2 + 2 = **8**

#### Mode 1: Manhattan Distance

h(A→D) = |0−4| + |0−3| = **7**, h(B→D) = |4−4| + |0−3| = **3**, h(C→D) = |2−4| + |3−3| = **2**

| Bước | Pop | f | g | h | Hành động |
|------|-----|---|---|---|-----------|
| 1 | A | 7 | 0 | 7 | Push B(g=5, h=3, f=8), C(g=4, h=2, f=6) |
| 2 | C | 6 | 4 | 2 | Push D(g=7, h=0, f=7), B(g=6, h=3, f=9 → g=5 cũ tốt hơn, skip) |
| 3 | D | 7 | 7 | 0 | **Goal reached!** Path: A → C → D (g = 7) |

**Manhattan ưu tiên C trước** nhờ h(C) = 2 rất nhỏ, dẫn đến thăm ít node hơn → **Hiệu quả khi goal nằm gần theo tổng khoảng cách Manhattan.**

#### Mode 2: Euclidean Distance

h(A→D) = √(16+9) = **5.0**, h(B→D) = √(0+9) = **3.0**, h(C→D) = √(4+0) = **2.0**

| Bước | Pop | f | g | h | Hành động |
|------|-----|---|---|---|-----------|
| 1 | A | 5.0 | 0 | 5.0 | Push B(g=5, h=3.0, f=8.0), C(g=4, h=2.0, f=6.0) |
| 2 | C | 6.0 | 4 | 2.0 | Push D(g=7, h=0, f=7), Push B(g=6 > 5, skip) |
| 3 | D | 7 | 7 | 0 | **Goal reached!** Path: A → C → D (g = 7) |

**Euclidean cho h thấp hơn Manhattan** → f ban đầu nhỏ hơn → khi start xa goal, Euclidean ước lượng chính xác hơn theo đường thẳng → **Ưu thế khi di chuyển tự do (không bị ràng buộc lưới).**

#### Mode 3: Chebyshev Distance

h(A→D) = max(4, 3) = **4**, h(B→D) = max(0, 3) = **3**, h(C→D) = max(2, 0) = **2**

| Bước | Pop | f | g | h | Hành động |
|------|-----|---|---|---|-----------|
| 1 | A | 4 | 0 | 4 | Push B(g=5, h=3, f=8), C(g=4, h=2, f=6) |
| 2 | C | 6 | 4 | 2 | Push D(g=7, h=0, f=7), Push B(g=6 > 5, skip) |
| 3 | D | 7 | 7 | 0 | **Goal reached!** Path: A → C → D (g = 7) |

**Chebyshev cho h nhỏ nhất** → f(start) thấp nhất → ít bị đánh giá quá cao → **Ưu thế khi cho phép di chuyển chéo với cùng chi phí di chuyển thẳng.**

### 2.3. So sánh tổng hợp

| Tiêu chí | Manhattan | Euclidean | Chebyshev |
|----------|-----------|-----------|-----------|
| h(A→D) | 7 | 5.0 | 4 |
| Nodes expanded | 3 | 3 | 3 |
| Path found | A→C→D | A→C→D | A→C→D |
| Total cost | 7 | 7 | 7 |
| **Ưu thế** | Di chuyển theo lưới | Di chuyển tự do | Di chuyển chéo |

**Phân tích:**

- **Manhattan** overestimate nhiều nhất → Có thể không admissible nếu đồ thị cho phép đi chéo → nhưng với đồ thị có trọng số tùy ý (Task 2), nó chỉ ảnh hưởng hiệu năng, không ảnh hưởng tính đúng (A* vẫn tìm được optimal nếu heuristic ≤ cost thực tế trên đồ thị).
- **Euclidean** là heuristic cân bằng nhất — ước lượng tốt cho không gian 2D.
- **Chebyshev** underestimate nhiều nhất → Khám phá nhiều node hơn ở đồ thị lớn, nhưng luôn admissible.

## Task 3 — Warehouse Robot Navigation with Obstacles

### 3.1. Mô tả bài toán

Robot di chuyển trên lưới `m × n` ô (0 = trống, 1 = tường). Robot có thể đi **8 hướng**:
- 4 hướng thẳng (Up, Down, Left, Right): chi phí **1.0**
- 4 hướng chéo (Up-Left, Up-Right, Down-Left, Down-Right): chi phí **1.5**

Tên mỗi node trong linked list là **hướng di chuyển** để đến ô đó (không phải tọa độ), ví dụ `"Up-Right"`.

Node Start bị loại bỏ khỏi linked list trả về (chỉ in các bước di chuyển từ Start → Goal).

**Hàm Heuristic:**
- **Mode 1 (Manhattan):** `h = |x₁ − x₂| + |y₁ − y₂|`
- **Mode 2 (Chebyshev):** `h = max(|x₁ − x₂|, |y₁ − y₂|)`

### 3.2. Tại sao Manhattan Overestimate trong bài này?

Khi robot đi **chéo 1 ô** (ví dụ từ `(0,0)` sang `(1,1)`):
- Chi phí thực tế: **1.5**
- Chebyshev: `max(1, 1)` = **1.0** → 1.0 ≤ 1.5 → **Admissible ✓**
- Manhattan: `|1| + |1|` = **2.0** → 2.0 > 1.5 → **Inadmissible ✗**

Hệ quả: Với Mode 1, A* bị "ảo giác" rằng đi chéo rất đắt. Nó sẽ không tìm ra đường tối ưu trong một số trường hợp (nhưng đây là hành vi có chủ đích của bài, thầy muốn kiểm tra xem sinh viên cài A* đúng chuẩn với mảng `visited` hay không).

### 3.3. Cài đặt A* chuẩn — Vai trò của mảng `visited`

Mảng `visited[id]` đóng vai trò **Closed Set** trong A* giáo khoa. Một khi một node đã được lấy ra khỏi MinHeap (được `pop()`), nó sẽ bị đánh dấu `visited = true` và **không bao giờ được xét lại**, ngay cả khi sau này thuật toán tìm thấy đường đi rẻ hơn đến nó.

Cấu trúc vòng lặp trong `findWarehousePath`:
```cpp
HeapNode temp = ncn.pop();
if (temp.id == goalPoint) break;          // Đến đích, dừng
if (visited[temp.id] == true) continue;   // Đã đóng, bỏ qua
visited[temp.id] = true;                  // Đánh dấu đóng

for (int i = 0; i < 8; i++) {
    // ...tính g_new cho 8 hướng...
    if (!visited[new_id] && g_new < g[new_id]) {  // Chỉ cập nhật nếu chưa đóng
        // push vào MinHeap, cập nhật parent, g, h
    }
}
```

## Task 4 — Evacuation Route Planning

### 4.1. Sự khác biệt so với Task 3

Task 4 giống hệt Task 3 về thuật toán A*, nhưng có thêm yêu cầu:
- **Input thêm:** `floorPlan[100][100]` (giống `warehouse`)
- **Output thêm:** `weightMatrix[100][100]` — sau khi tìm được đường đi, ghi lại `g(x,y)` cho mỗi ô **nằm trong path** (kể cả Start); các ô ngoài path giữ nguyên `= 0`.

### 4.2. Cách điền weightMatrix

Trong vòng truy vết ngược `while (parents[i] != -1)`, mỗi ô được truy vết sẽ được gán:
```cpp
int x = parents[i] / 100;
int y = parents[i] % 100;
weightMatrix[x][y] = g[parents[i]];
```
Sau vòng lặp, ô goal cũng được ghi:
```cpp
weightMatrix[exitX][exitY] = g[goalPoint];
```
